# Phase 4 – Incident Detection and Response

## 1. Project Overview

**Project:** Enterprise Network Security Infrastructure  
**Phase:** 4 – Incident Detection and Response  
**Platform:** Cisco Packet Tracer

### Objective

To simulate a network security incident involving an unauthorized device connected to a protected switch port. The objective was to detect the violation, review the security event, contain the incident, restore the authorized connection, and verify network connectivity.

## 2. Incident Scenario

An unauthorized device was connected to switch port Fa0/8, which was configured with port security.

The port was configured with:
- Maximum MAC addresses: 1
- Sticky MAC learning
- Violation mode: Shutdown
- Access VLAN: 60

The unauthorized device presented a different MAC address from the authorized sticky MAC address.

## 3. Initial Security Baseline

Before the incident, the authorized device was learned through sticky MAC address security.

### Verification Command

```text
show port-security interface fa0/8
```

### Baseline Results

- Port status: Secure-up
- Violation mode: Shutdown
- Maximum MAC addresses: 1
- Sticky MAC addresses: 1
- Security violation count: 0

The baseline confirmed that the port was operating normally before the incident.

## 4. Unauthorized Device Detection

When the unauthorized device was connected to Fa0/8, the switch detected a MAC address violation.

### Verification Commands

```text
show port-security interface fa0/8
show interfaces status
```

### Incident Results

- Port status: Secure-shutdown
- Interface status: err-disabled
- Violation mode: Shutdown
- Security violation count: 1
- Authorized sticky MAC address: `0060.4791.E45C`.
- Unauthorized MAC addresses visible in the supplied captures: `0030.A334.315A` and `0030.F2BC.D056`.

The supplied captures show two different unauthorized MAC addresses in separate test captures. They should not be described as the same device or a single continuous event. The switch automatically disabled the protected port when an unauthorized device exceeded the configured MAC address security policy.

## 5. Incident Detection Through Syslog

The Syslog Server was used to review the security event generated by the network device.

### Monitoring Location

**Server:** Syslog Server  
**IP Address:** 192.168.60.10  
**Service:** SYSLOG  
**Transport:** UDP  
**Port:** 514

The Syslog event provides centralized evidence of the security incident.

### Security Benefit

- Centralized network event visibility.
- Support for incident investigation.
- Easier review of device security events.
- Improved network monitoring.

## 6. Incident Containment

The unauthorized device was disconnected from the protected switch port.

The shutdown violation mode prevented the affected port from continuing normal communication after the violation.

This contained the incident at the switch access-port level.

## 7. Port Recovery

After disconnecting the unauthorized device, the authorized Security Testing PC was reconnected.

The interface was manually recovered.

### Recovery Commands

```text
enable
configure terminal
interface fa0/8
shutdown
no shutdown
end
```

### Recovery Verification

```text
show port-security interface fa0/8
show interfaces status
```

Observed recovery evidence:

- Port status: Secure-up.
- Authorized sticky MAC address retained: `0060.4791.E45C`.
- The authorized device was reconnected after the unauthorized device was removed.
- The port was recovered using `shutdown` followed by `no shutdown`.

## 8. Post-Incident Connectivity Test

After recovery, connectivity was tested from the authorized Security Testing PC to the Security Monitoring VLAN gateway.

### Test Command

```text
ping 192.168.60.1
```

### Observed Result

The supplied post-incident connectivity screenshot shows 4 packets sent, 4 received, and 0% packet loss when testing connectivity to `192.168.60.1`. This confirms that the authorized device could reach the Security Monitoring VLAN gateway after recovery.

## 9. Incident Response Workflow

1. Establish the authorized port-security baseline.
2. Connect the unauthorized test device.
3. Detect the MAC address violation.
4. Confirm the port enters secure-shutdown state.
5. Review the Syslog security event.
6. Disconnect the unauthorized device.
7. Reconnect the authorized device.
8. Recover the switch interface.
9. Verify port-security status.
10. Test authorized network connectivity.

## 10. Security Verification Checklist

- [ ] Authorized MAC address learned through sticky MAC.
- [ ] Maximum MAC address limit set to 1.
- [ ] Shutdown violation mode configured.
- [ ] Unauthorized device connected for testing.
- [ ] Security violation detected.
- [ ] Port entered secure-shutdown state.
- [ ] Violation count increased.
- [ ] Syslog event reviewed.
- [ ] Unauthorized device disconnected.
- [ ] Authorized device reconnected.
- [ ] Port recovered successfully.
- [ ] Post-incident connectivity verified.

## 11. Phase 4 Outcome

The incident response exercise demonstrated how switch port security can detect and contain an unauthorized device connection.

The exercise covered detection, containment, centralized event review, recovery, and post-incident verification.

**Status:** The Packet Tracer unauthorized-device incident, port-security shutdown, Syslog event review, authorized-port recovery, and post-incident connectivity test were demonstrated. The supplied evidence includes a successful post-recovery ping with 4/4 replies.
